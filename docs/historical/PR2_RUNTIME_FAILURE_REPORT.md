# OmaFiles PR #2: D-Bus Activation Failure Report

## Root Cause Analysis
The failure of the file picker to appear in Zen Browser is caused by a **D-Bus service activation failure** due to a path mismatch.

When Zen Browser requests a file chooser via the portal, `xdg-desktop-portal` correctly routes the request to the `omafiles` backend. The system D-Bus daemon then attempts to launch the Python backend daemon using the `.service` file generated by `install-integrations.sh`.

However, the generated service file (`~/.local/share/dbus-1/services/org.freedesktop.impl.portal.desktop.omafiles.service`) contains the following directive:
```ini
Exec=/home/josema/.local/share/omafiles/scripts/dbus-filechooser.py
```

The script `dbus-filechooser.py` **does not exist** at that path. As a result, the D-Bus daemon fails to activate the service and drops the request. Zen Browser receives a failure/cancellation from the portal and silently does nothing, which matches the reported symptoms exactly ("Nothing happens. No picker window appears. No error dialog appears").

## Why the Path is Incorrect
In `install-integrations.sh`, the resource directory is hardcoded:
```bash
RES_DIR="${XDG_DATA_HOME:-$HOME/.local/share}/omafiles"
```
The script explicitly comments that this path *"Requires `cmake --install` (which copies scripts/ and assets/ here)."* 

Because OmaFiles is a Quickshell plugin operating directly from `~/.config/omarchy/plugins/omafiles/`, the `cmake --install` step is frequently skipped by users who only compile the standalone binary or run the integration script directly from the repository.

## The Fix
To resolve this issue, the user must either:

1. **Run `cmake --install`**: Execute this from the build directory to properly copy the `scripts/` folder into `~/.local/share/omafiles/`.
   ```bash
   cd ~/.config/omarchy/plugins/omafiles/build
   cmake --install .
   ```
2. **Modify `install-integrations.sh`**: If OmaFiles is intended to run directly from the config repository without a separate installation step, `install-integrations.sh` should be patched to use `SELF_RES` instead of `RES_DIR` for the `Exec` paths in the generated `.service` files:
   ```bash
   Exec=$SELF_RES/scripts/dbus-filechooser.py
   ```

## Execution Trace Summary
1. Zen Browser calls `org.freedesktop.portal.FileChooser.OpenFile`.
2. `xdg-desktop-portal` reads `portals.conf`, selects the `omafiles` backend, and calls `OpenFile` on `org.freedesktop.impl.portal.desktop.omafiles`.
3. `dbus-daemon` receives the activation request and reads `org.freedesktop.impl.portal.desktop.omafiles.service`.
4. `dbus-daemon` attempts to execute `/home/josema/.local/share/omafiles/scripts/dbus-filechooser.py`.
5. **[FAILURE]** The file is not found. `dbus-daemon` returns an error to `xdg-desktop-portal`.
6. `xdg-desktop-portal` aborts the portal request. Zen Browser sees the cancellation and does nothing.
